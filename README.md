# AI-помощник для товарных описаний

Прототип на Python: принимает данные о приборе, вызывает OpenAI API и возвращает черновик карточки товара в JSON. Формирует SEO-заголовок, описание, поисковые запросы и короткий блок для менеджера. Отдельно сообщает о недостающих данных.

## Установка и тесты

Python 3.12. Команды для Ubuntu, из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pytest -q
```

Тесты проверяют чтение данных, валидацию карточки, локальный пример, ошибки API и повторную генерацию. Тесты работают без API-ключа и обращения к модели.

## Настройка и запуск

```bash
cp .env.example .env
```

В `.env` заполнить `OPENAI_API_KEY`. Поле `OPENAI_MODEL` содержит имя модели; его можно заменить на доступную модель с поддержкой Responses API и JSON Schema. Переменные окружения имеют приоритет над `.env`. Файл `.env` исключён из Git.

Локально показать пример карточки-заглушки без обращения к API:

```bash
python main.py --local
```

Указать другой JSON с товаром можно через `--product`:

```bash
python main.py --local --product data/products.json
```

Для генерации через API запустить `python main.py` или выполнить:

```python
import json
from catalog import load_products
from generator import create_client, generate_card

product = load_products("data/product_example.json")[0]
with create_client() as client:
    card = generate_card(product, client)

print(json.dumps(card, ensure_ascii=False, indent=2))
```

Этот пример обращается к настоящему API. `data/product_example.json` содержит учебный пример из ТЗ. Для товара из каталога использовать `data/products.json`.

## Входные данные

JSON с одним товаром или непустым списком товаров:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {"диапазон измерений": "0-1,6 МПа", "класс точности": "1,5"},
  "description": "Прибор предназначен для измерения избыточного давления."
}
```

Значения характеристик передаются строками для сохранения единиц и записи чисел. Пустая строка, null и отсутствующее поле означают отсутствие данных. Неверный тип поля или повреждённый файл вызывает исключение с пояснением.

## Файлы проекта

- `catalog.py`: чтение JSON и XML, нормализация, определение пустых полей.
- `generator.py`: клиент API, генерация и проверка карточки.
- `prompt.txt`: инструкции модели и правила работы с неполными данными.
- `tests/`: проверки каждой функции и сценариев обработки ошибок.
- `data/products.json`: два предварительно выбранных товара из каталога.
- `data/product_example.json`: учебный пример с характеристиками.
- `data/source_info.json`: адрес, дата и контрольная сумма исходного снимка.

## Результат и ограничения

`status=draft`: ответ прошёл программные проверки. Заголовок занимает до 70 символов, описание 800-1200 символов с пробелами, поисковых запросов от 3 до 5. Это черновик для проверки менеджером.

`status=needs_data`: достоверного материала недостаточно. Описание может быть короче, а поле `reason` объясняет, что необходимо добавить. `missing_fields` перечисляет пустые поля. Характеристики копируются кодом из входа, пустые значения заменяются на «данных нет».

В каталоге нет описаний и технических характеристик: параметры содержат артикулы и коды товаров. Эти идентификаторы хранятся отдельно от `specs`. Для двух примеров из каталога ожидается `needs_data`.

Промпт запрещает добавлять свойства из внешних знаний или расшифровывать название модели. Ответ запрашивается по JSON Schema, затем проверяется в Python. При нарушении формата или правил допускается одна повторная генерация. Таймаут, отказ модели и ошибки API завершают запрос без автоматических повторов.

Числовая проверка обнаруживает новые числа, но не выявляет известное число в другом контексте, подмену единиц или выдуманное свойство без чисел. Карточку необходимо сверить с источником. Частотность поисковых запросов не проверяется. Режим `--local` выводит демонстрационную заглушку, он не генерирует содержание карточки.
